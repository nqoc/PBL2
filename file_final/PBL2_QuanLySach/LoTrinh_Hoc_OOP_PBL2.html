  • Hiểu tại sao phải tách .h (khai báo) và .cpp (định nghĩa).

Lý thuyết cốt lõi

1. Cài đặt công cụ

Theo đúng tài liệu Hướng dẫn sử dụng Visual Studio Code của môn học: cài VS Code → cài MinGW-w64 qua MSYS2 → thêm C:\msys64\mingw64\bin vào biến môi trường PATH → cài extension C/C++ của Microsoft. Kiểm tra bằng cách mở terminal và gõ:

g++ --version

Nếu ra số phiên bản là xong. Nếu báo “not found” thì PATH chưa đúng, làm lại bước thêm PATH.

2. Vì sao phải chia tệp?

Chương trình PBL2 cuối cùng có gần 6.000 dòng. Nếu nhét vào một tệp main.cpp thì: sửa một dòng phải dịch lại toàn bộ, hai người không thể làm song song, và không ai đọc nổi. Quy ước chuẩn:

  • Tệp .h (header) — khai báo: “lớp này có gì”. Người dùng lớp chỉ cần đọc tệp này.
  • Tệp .cpp — định nghĩa: “làm như thế nào”. Chi tiết bị che đi.

3. Include guard — chống khai báo lặp

Nếu hai tệp cùng #include "Sach.h", trình biên dịch sẽ thấy lớp Sach hai lần và báo lỗi. Mọi tệp .h phải được bọc như sau:

#ifndef SACH_H        // nếu chưa định nghĩa nhãn SACH_H
#define SACH_H        // thì định nghĩa nó

class Sach { ... };   // và đưa nội dung vào

#endif // SACH_H   -> lần include thứ hai sẽ bị bỏ qua

4. Quá trình biên dịch 2 bước

// Bước 1: mỗi .cpp -> một tệp đối tượng .o (biên dịch riêng lẻ)
g++ -std=c++17 -Wall -Wextra -Iinclude -c src/Sach.cpp -o build/Sach.o

// Bước 2: nối tất cả .o thành tệp chạy (liên kết)
g++ -std=c++17 build/*.o -o QuanLySach.exe

// Trong thực tế, khi dự án còn nhỏ có thể gộp một dòng:
g++ -std=c++17 -Wall -Wextra -Iinclude src/*.cpp -o QuanLySach.exe

Ý nghĩa các tuỳ chọn: -std=c++17 chọn chuẩn ngôn ngữ; -Iinclude nói với g++ “tìm tệp .h trong thư mục include”; -Wall -Wextra bật mọi cảnh báo. Hãy luôn bật cảnh báo và sửa cho hết — đa số lỗi khó tìm đều được cảnh báo báo trước.

5. Tệp build.bat để không phải gõ lại

@echo off
g++ -std=c++17 -Wall -Wextra -Iinclude src\*.cpp -o QuanLySach.exe
if errorlevel 1 ( echo === LOI BIEN DICH === & pause & exit /b 1 )

Chặng 1 — Từ C sang C++ Tuần 1

Mục tiêu

  • Dùng std::string thay cho char*, cin/cout thay cho scanf/printf.
  • Hiểu tham chiếu (&) — thứ xuất hiện gần như mọi dòng trong PBL2.

Lý thuyết cốt lõi

1. Nhập xuất và chuỗi

#include <iostream>
#include <string>
using namespace std;

int main() {
    string ten;                       // tự quản lý bộ nhớ, không lo tràn mảng
    cout << "Ten sach: ";
    getline(cin, ten);                // đọc CẢ DÒNG, kể cả khoảng trắng

    cout << "Do dai = " << ten.size() << "\n";
    cout << "Ghep   = " << ten + " (moi)" << "\n";
    if (ten.find("Toan") != string::npos) cout << "Co chua chu Toan\n";
    return 0;
}

Cái bẫy kinh điển: trộn cin >> với getline

cin >> n; đọc số nhưng để lại ký tự Enter trong bộ đệm, làm getline ngay sau đó đọc được chuỗi rỗng. Trong PBL2 chúng ta giải quyết bằng cách luôn dùng getline rồi tự chuyển chuỗi sang số — đó chính là lý do tồn tại của Nhap::soNguyen() trong TienIch.cpp:

string s;  getline(cin, s);
istringstream is(s);
int v;   char thua;
if (!(is >> v) || (is >> thua)) cout << "Khong phai so nguyen!\n";

2. Tham chiếu — khái niệm quan trọng nhất của chặng này

Tham chiếu là tên gọi khác của một biến đã có. Không phải bản sao, không phải con trỏ.

void tang(int  x) { x = x + 1; }   // truyền GIÁ TRỊ: sửa bản sao -> vô tác dụng
void tang(int& x) { x = x + 1; }   // truyền THAM CHIẾU: sửa chính biến gốc

int a = 5;
tang(a);        // a = 6

Có ba cách truyền tham số, và PBL2 dùng cả ba một cách có chủ ý:

Cách viếtÝ nghĩaDùng khi nào
void f(int x)bản saokiểu nhỏ (int, double, bool)
void f(string& s)tham chiếu, được sửamuốn hàm thay đổi đối tượng gốc
void f(const string& s)tham chiếu, không được sửamặc định nên dùng cho mọi đối tượng lớn — nhanh (không sao chép) và an toàn

Vì vậy trong PBL2 bạn thấy khắp nơi: void setTen(const std::string& s), void them(const T& x), bool operator==(const Sach& k) const.

3. Nạp chồng hàm và tham số mặc định

// Cùng tên, khác danh sách tham số -> đây là "đa hình hàm" (tĩnh)
string doiSangChuoi(int v);
string doiSangChuoi(double v, int soLeThapPhan = 0);   // có tham số mặc định

doiSangChuoi(5);            // gọi bản int
doiSangChuoi(3.14159, 2);   // gọi bản double -> "3.14"
doiSangChuoi(3.14159);      // gọi bản double, soLeThapPhan = 0 -> "3"

Hai hàm này có thật trong TienIch.h của dự án.

4. Bộ nhớ động: new / delete

int*  p  = new int(10);       delete   p;      // một biến
int*  a  = new int[100];      delete[] a;      // một mảng -> PHẢI có []

Ba luật sinh tử về bộ nhớ động

  1. new đi với delete, new[] đi với delete[]. Nhầm là hỏng.
  2. Mỗi new phải có đúng một delete. Thiếu → rò rỉ bộ nhớ. Thừa → chương trình đổ.
  3. Sau delete p, con trỏ p trở thành rác. Đừng dùng lại nó.

Trong PBL2, chỉ có một nơi được phép new Sach và một nơi delete nó: lớp QuanLySach. Tập trung trách nhiệm bộ nhớ vào một chỗ là cách duy nhất để không rò rỉ trong dự án lớn.

Chặng 2 — Lớp và đối tượng: tính đóng gói Tuần 2

Mục tiêu

  • Viết được một lớp hoàn chỉnh: thuộc tính private, phương thức public, hàm tạo, hàm hủy.
  • Hiểu vì sao phải che dữ liệu chứ không chỉ biết cú pháp.
  • Nắm this, hàm hằng const, thành viên static, hàm bạn friend.

Lý thuyết cốt lõi

1. Từ struct của C đến class của C++

Trong C, bài toán quản lý ngày tháng viết thế này:

struct Date { int ngay, thang, nam; };
Date d;
d.ngay  = 32;      // SAI nhưng trình biên dịch vẫn cho qua!
d.thang = 2;  d.ngay = 30;   // SAI, ai kiểm tra?

Vấn đề: dữ liệu “trần trụi”, bất kỳ dòng code nào cũng gán được giá trị vô nghĩa. Khi phần mềm lớn lên, đây là nguồn lỗi số một. Giải pháp của OOP là đóng gói: gói dữ liệu lại, chỉ cho ra ngoài qua các cửa có kiểm soát.

class Ngay {
private:                                // KHÔNG ai bên ngoài chạm được
    int ngay, thang, nam;

public:                                 // giao diện dùng của lớp
    Ngay() : ngay(1), thang(1), nam(2024) {}          // hàm tạo mặc định

    void setNgay(int n) {
        if (n < 1 || n > 31) return;    // CHỐT KIỂM TRA nằm ngay tại đây
        ngay = n;
    }
    int getNgay() const { return ngay; }              // const: chỉ đọc
};

Từ khoáAi truy cập đượcDùng cho

3. Hàm tạo và danh sách khởi tạo

class Sach {
protected:
    std::string maSach, tenSach;
    int    namXuatBan;
    double giaBan;
public:
    Sach();                                                // hàm tạo mặc định
    Sach(const std::string& ma, const std::string& ten,
         int nam, double gia);                             // hàm tạo có tham số
    virtual ~Sach();                                       // hàm hủy (Chặng 6 sẽ giải thích virtual)
};

// --- trong Sach.cpp ---
Sach::Sach() : namXuatBan(2024), giaBan(0) {}              // danh sách khởi tạo

2. Vì sao << phải là hàm bạn, không phải thành viên?

3. Quy tắc ba (Rule of Three)

Nếu lớp của bạn tự quản lý bộ nhớ động (có con trỏ new bên trong), trình biên dịch sinh sẵn hàm tạo sao chép và toán tử gán, nhưng nó chỉ sao chép giá trị con trỏ — hai đối tượng sẽ trỏ vào cùng một vùng nhớ, và khi cả hai bị hủy thì vùng nhớ đó bị delete hai lần → chương trình đổ.

template <class T>
class Vector {
    T* duLieu;  std::size_t soPhanTu, dungLuong;
public:
    ~Vector()                       { delete[] duLieu; }          // (1) hàm hủy
    Vector(const Vector<T>& khac);                                // (2) hàm tạo sao chép
    Vector<T>& operator=(const Vector<T>& khac);                  // (3) toán tử gán
};

template <class T>
Vector<T>& Vector<T>::operator=(const Vector<T>& khac) {
    if (this == &khac) return *this;         // BẮT BUỘC: chặn tự gán cho chính mình
    delete[] duLieu;                         // giải phóng vùng cũ
    duLieu = 0; soPhanTu = 0; dungLuong = 0;
    baoDamChua(khac.soPhanTu);               // cấp vùng mới
    for (std::size_t i = 0; i < khac.soPhanTu; ++i) duLieu[i] = khac.duLieu[i];
    soPhanTu = khac.soPhanTu;                // SAO CHÉP SÂU
    return *this;
}

1. Composition — “là bộ phận của”, chết theo chủ

Sai phổ biến: gán trực tiếp thuộc tính lớp cha trong thân hàm tạo (this->hoTen = hoTen_;). Nó chạy được nếu thuộc tính là protected, nhưng bạn đã bỏ qua mọi kiểm tra hợp lệ mà lớp cha viết sẵn, và không dùng lại được code khởi tạo của cha. Luôn gọi hàm tạo lớp cha qua danh sách khởi tạo.

Chặng 6 — Đa hình, hàm ảo, lớp trừu tượng Tuần 4–5

Đây là chặng quan trọng nhất của cả môn học. Nếu chỉ nắm được một chương duy nhất, hãy nắm chương này.

Mục tiêu

  • Hiểu liên kết tĩnh vs liên kết động và vì sao thiếu virtual là sai.
  • Viết được lớp trừu tượng bằng hàm thuần ảo.
  • Biết vì sao hàm hủy của lớp cơ sở phải là virtual.
  • Cài được hàm xưởng (factory) và nhanBan() (clone).

Lý thuyết cốt lõi

1. Vấn đề: gọi con trỏ lớp cha thì được hàm nào?

class Sach {
public:
    std::string loaiSach() const { return "Sach"; }        // CHƯA có virtual
};
class SachVanHoc : public Sach {
public:
    std::string loaiSach() const { return "Van hoc"; }
};

SachVanHoc vh;
Sach* p = &vh;
cout << p->loaiSach();     // In ra "Sach"  -> SAI so với mong đợi!

Vì trình biên dịch chỉ nhìn kiểu tĩnh của p (là Sach*) và quyết định ngay lúc dịch — gọi là liên kết tĩnh (static binding / early binding).

2. Giải pháp: từ khoá virtual

class Sach {
public:
    virtual std::string loaiSach() const { return "Sach"; }   // hàm ẢO
};

SachVanHoc vh;
Sach* p = &vh;
cout << p->loaiSach();     // In ra "Van hoc"  -> ĐÚNG

virtual yêu cầu trình biên dịch hoãn việc chọn hàm đến lúc chạy, dựa vào kiểu động — vật mà con trỏ đang thực sự trỏ tới. Đó là liên kết động (dynamic binding / late binding), và đa hình động chính là điều nó tạo ra.

Liên kết tĩnhLiên kết động
Quyết định lúcbiên dịchchạy
Dựa vàokiểu khai báo (kiểu tĩnh)đối tượng thật (kiểu động)
Cầnkhông cần gìhàm virtual + gọi qua con trỏ / tham chiếu
Chi phíkhôngmột lần tra bảng hàm ảo (rất nhỏ)

Điều kiện để đa hình hoạt động — thiếu một là mất tác dụng

  1. Hàm ở lớp cha phải khai báo virtual.
  2. Hàm ở lớp con phải trùng khớp hoàn toàn: cùng tên, cùng danh sách tham số, cùng kiểu trả về, cùng có/không có const. Lệch một chi tiết là thành hàm mới, không phải ghi đè.
  3. Phải gọi qua con trỏ hoặc tham chiếu lớp cha. Gọi qua đối tượng giá trị thì đã bị slicing, không còn gì để đa hình.

3. Hàm thuần ảo và lớp trừu tượng

“Một cuốn sách chung chung” là cái gì? Nó không có giá giảm cụ thể, không có tên loại. Vậy ta cấm tạo đối tượng Sach:

class Sach {
public:
    // = 0 nghĩa là: KHAI BÁO mà không định nghĩa -> hàm THUẦN ẢO
    virtual std::string loaiSach() const = 0;
    virtual std::string maLoai()   const = 0;
    virtual Sach*       nhanBan()  const = 0;
};

// Sach s;          // LỖI BIÊN DỊCH: Sach là lớp trừu tượng
Sach* p = new SachVanHoc(...);   // OK: con trỏ tới lớp cha thì được

Lớp có ít nhất một hàm thuần ảo là lớp trừu tượng (Abstract Base Class). Nó buộc mọi lớp con phải cài đặt các hàm đó nếu muốn tạo được đối tượng — một cách “ra đề” cho lớp con rất mạnh.

4. Hàm ảo vs hàm thuần ảo — chọn cái nào?

5. Đa hình trong PBL2 — mấu chốt của toàn bộ chương trình

// Một mảng duy nhất chứa CẢ BA loại sách:
Vector<Sach*> ds;
ds.them(new SachGiaoKhoa("GK001", ..., "Toan", 12));
ds.them(new SachVanHoc  ("VH001", ..., "Tieu thuyet", "Khong"));
ds.them(new SachThieuNhi("TN001", ..., 6, true));

// In bảng: một vòng lặp duy nhất, KHÔNG cần if/else theo loại sách
for (size_t i = 0; i < ds.kichThuoc(); ++i) {
    ds[i]->xuatDong();      // mỗi loại tự in dòng của mình
    cout << "\n";
}

// Tính tiền: mỗi loại tự biết mức giảm giá của nó

for (size_t i = 0; i < ds.kichThuoc(); ++i)
    t += ds[i]->giaSauGiam();   // gọi tiLeGiamGia() của ĐÚNG lớp con

Hãy hình dung nếu không có đa hình: mỗi chỗ hiển thị hay tính tiền sẽ phải viết if (loai == "GK") ... else if (loai == "VH") .... Thêm một loại sách thứ tư là phải sửa hàng chục chỗ. Với đa hình, bạn chỉ cần thêm một lớp con và một dòng trong hàm xưởng.

6. Hàm hủy ảo — lỗi rò rỉ bộ nhớ kinh điển

class Sach            { public: ~Sach(); };                // KHÔNG virtual -> SAI
class SachVanHoc : public Sach { ... };

Sach* p = new SachVanHoc(...);
delete p;   // CHỈ gọi ~Sach(), KHÔNG gọi ~SachVanHoc() -> rò rỉ tài nguyên riêng
class Sach { public: virtual ~Sach(); };                   // ĐÚNG
// delete p; -> gọi ~SachVanHoc() rồi tự động ~Sach()

Quy tắc không có ngoại lệ: lớp nào được thiết kế để làm lớp cơ sở thì hàm hủy phải là virtual — kể cả khi thân hàm rỗng. Trong PBL2: Nguoi, Sach, DanhMuc, ChungTu đều có virtual ~...().

7. Hàm xưởng (factory) — tạo đúng loại từ một chuỗi

Khi đọc tệp, ta chỉ có chuỗi "GK". Làm sao biết phải new lớp nào?

Sach* taoSachTheoMaLoai(const std::string& maLoai) {
    if (maLoai == "GK") return new SachGiaoKhoa();
    if (maLoai == "VH") return new SachVanHoc();
    if (maLoai == "TN") return new SachThieuNhi();
    throw LoiDuLieu("Ma loai sach khong hop le: " + maLoai);
}

// Dùng khi đọc tệp - QuanLySach::docFile()

Sach* s = taoSachTheoMaLoai(p[0]);   // p[0] là "GK"/"VH"/"TN"

them(s);

Đây là chỗ duy nhất trong toàn dự án còn if theo loại sách. Mọi nơi khác đều dùng đa hình.

8. nhanBan() — hàm tạo sao chép “ảo”

Bạn không thể làm hàm tạo thành virtual. Nếu chỉ có Sach* p mà muốn tạo bản sao đúng loại, dùng mẫu clone:

class Sach          { public: virtual Sach* nhanBan() const = 0; };
Sach* SachVanHoc::nhanBan() const { return new SachVanHoc(*this); }   // mỗi con tự nhân bản

Sach* ban = p->nhanBan();    // đúng loại, không bị slicing

Chặng 7 — Template: lập trình tổng quát Tuần 5–6

Mục tiêu

  • Viết được hàm template và lớp template.
  • Hiểu vì sao mã template phải nằm trong tệp .h.
  • Dùng một lớp KhoDuLieu<T> duy nhất để quản lý 8 loại đối tượng khác nhau.

Lý thuyết cốt lõi

1. Vấn đề: cùng thuật toán, khác kiểu dữ liệu

void doiCho(int&    a, int&    b) { int    t = a; a = b; b = t; }
void doiCho(double& a, double& b) { double t = a; a = b; b = t; }
void doiCho(string& a, string& b) { string t = a; a = b; b = t; }
// ... còn bao nhiêu kiểu nữa? Cùng một logic bị chép lại.

2. Hàm template

template <class T>
void doiCho(T& a, T& b) { T t = a; a = b; b = t; }

int x = 1, y = 2;         doiCho(x, y);           // T suy ra là int
string s = "a", u = "b";  doiCho(s, u);           // T suy ra là string
doiCho<double>(m, n);                             // chỉ định tường minh nếu cần

Trình biên dịch sẽ sinh ra một bản hàm riêng cho mỗi kiểu bạn dùng — không mất hiệu năng so với viết tay, chỉ tốn thêm thời gian dịch.

3. Lớp template

template <class T>
class Vector {
private:
    T*          duLieu;
    std::size_t soPhanTu, dungLuong;
public:
    Vector();
    Vector(const Vector<T>& khac);
    Vector<T>& operator=(const Vector<T>& khac);
    ~Vector();

    std::size_t kichThuoc() const { return soPhanTu; }
    T&          operator[](std::size_t i)       { return duLieu[i]; }
    const T&    operator[](std::size_t i) const { return duLieu[i]; }
    void        them(const T& x);
};

// Định nghĩa hàm thành viên NGOÀI lớp: phải lặp lại template và tên có <T>
template <class T>
void Vector<T>::them(const T& x) {
    baoDamChua(soPhanTu + 1);
    duLieu[soPhanTu++] = x;
}

Khác với hàm template, lớp template phải chỉ kiểu tường minh khi tạo đối tượng (vì trình biên dịch cần biết kích thước bộ nhớ):

Vector<Sach*>     dsSach;      // OK
Vector<KhachHang> dsKhach;     // OK
// Vector v;                   // LỖI

Luật vàng: mã template nằm trong .h

Trình biên dịch chỉ sinh mã cho Vector<int> tại chỗ bạn dùng nó. Nếu bạn đặt định nghĩa trong Vector.cpp, tệp đó được dịch riêng và không biết bạn cần Vector<int> — kết quả là lỗi liên kết undefined reference. Vì vậy trong PBL2, cả 5 tệp template (Vector.h, DanhSachLienKet.h, BangBam.h, ThuatToan.h, KhoDuLieu.h) đều không có tệp .cpp đi kèm.

4. Template với hàm so sánh truyền vào

template <class T, class SoSanh>
void quickSort(Vector<T>& a, SoSanh cmp) { ... }

// cmp có thể là con trỏ hàm:

5. Kỹ thuật quan trọng: giao dịch “tất cả hoặc không gì”

Khi lưu một hoá đơn 5 dòng, nếu dòng thứ 4 thiếu hàng mà 3 dòng đầu đã trừ kho rồi thì dữ liệu sai vĩnh viễn. Cách làm đúng: kiểm tra toàn bộ trước, chỉ sửa khi mọi thứ hợp lệ.

void CuaHang::ghiNhanHoaDon(HoaDon& hd) {
    if (hd.soDong() == 0) throw LoiDuLieu("Hoa don chua co dong hang nao.");

    // BƯỚC 1: kiểm tra TẤT CẢ, chưa sửa gì cả
    const Vector<DongChiTiet>& dong = hd.cacDong();
    for (size_t i = 0; i < dong.kichThuoc(); ++i) {
        Sach* s = khoSach.timTheoMa(dong[i].getMaSach());
        if (s == 0) throw LoiKhongTimThay("Sach " + dong[i].getMaSach());
        if (dong[i].getSoLuong() > s->getSoLuong()) {
            ostringstream os;
            os << "Sach " << s->getMa() << " chi con " << s->getSoLuong() << " cuon.";
            throw LoiTonKho(os.str());        // thoát ra, dữ liệu VẪN NGUYÊN VẸN
        }
    }

    // BƯỚC 2: đến đây chắc chắn hợp lệ -> mới trừ kho
    for (size_t i = 0; i < dong.kichThuoc(); ++i)
        khoSach.timTheoMa(dong[i].getMaSach())->banBotKho(dong[i].getSoLuong());

    // BƯỚC 3: cộng điểm khách hàng   BƯỚC 4: lưu hoá đơn
    if (!hd.getMaKhachHang().empty()) {
        KhachHang* kh = khoKhachHang.timTheoMa(hd.getMaKhachHang());
        if (kh != 0) kh->congDiemTheoHoaDon(hd.thanhToan());
    }
    if (hd.getMa().empty()) hd.setMa(sinhMaHoaDon());
    khoHoaDon.them(hd);
}

void Sach::fromCSV(const std::vector<std::string>& p) {
    if (p.size() < 12) throw LoiFile("Dong du lieu Sach thieu truong.");

bool KhoDuLieu<T>::docFile(const std::string& tenTep) {

    if (!f) return false;                       // chưa có tệp: bình thường ở lần chạy đầu

1. Mảng động — vì sao tăng gấp đôi?

template <class T>
void Vector<T>::baoDamChua(std::size_t canCo) {
    if (canCo <= dungLuong) return;                 // còn chỗ, không làm gì
    std::size_t moi = (dungLuong == 0) ? 4 : dungLuong * 2;   // TĂNG GẤP ĐÔI
    while (moi < canCo) moi *= 2;
    T* vungMoi = new T[moi];
    for (std::size_t i = 0; i < soPhanTu; ++i) vungMoi[i] = duLieu[i];
    delete[] duLieu;
    duLieu = vungMoi;  dungLuong = moi;
}

template <class T>
void Vector<T>::them(const T& x) {
    baoDamChua(soPhanTu + 1);
    duLieu[soPhanTu++] = x;
}

Nếu mỗi lần thêm chỉ tăng 1 ô, thêm n phần tử phải sao chép 1+2+…+n ≈ n²/2 lần → O(n²). Tăng gấp đôi thì tổng số lần sao chép là n+n/2+n/4+… < 2n → mỗi lần thêm tốn O(1) trung bình khấu hao. Cái giá là dùng thừa nhiều nhất 2× bộ nhớ.

template <class T>
class DanhSachLienKet {
private:
    struct Nut {                      // struct lồng bên trong: chỉ lớp này dùng
        T    duLieu;
        Nut* tiep;
        Nut(const T& x) : duLieu(x), tiep(0) {}

    void themCuoi(const T& x) {
        Nut* moi = new Nut(x);
        if (dau == 0) { dau = moi; cuoi = moi; }        // danh sách rỗng
        else          { cuoi->tiep = moi; cuoi = moi; } // O(1) nhờ giữ con trỏ cuoi
        ++soPhanTu;
    }
    void xoaHet() {
        Nut* p = dau;
        while (p != 0) { Nut* t = p->tiep; delete p; p = t; }   // giữ tiep TRƯỚC khi delete
        dau = 0; cuoi = 0; soPhanTu = 0;

    class BoDuyet {
        Nut* hienTai;
    public:
        BoDuyet(Nut* p) : hienTai(p) {}
        T&       operator*()  const { return hienTai->duLieu; }
        BoDuyet& operator++()       { hienTai = hienTai->tiep; return *this; }
        bool operator!=(const BoDuyet& k) const { return hienTai != k.hienTai; }
    };
    BoDuyet begin() const { return BoDuyet(dau); }
    BoDuyet end()   const { return BoDuyet(0); }
};

3. Bảng băm — tra cứu O(1)

Ý tưởng: từ khoá "GK001" tính ra một số, dùng số đó làm chỉ số ô. Hai khoá khác nhau có thể cho cùng ô (va chạm) → mỗi ô giữ một danh sách nối kết.

template <class V>
class BangBam {
private:
    struct Nut { std::string khoa; V giaTri; Nut* tiep; ... };
    Nut**       bang;        // mảng con trỏ, mỗi ô là đầu một chuỗi nối kết
    std::size_t soBucket, demSo;

    // Hàm băm Horner cơ số 31 (31 là số nguyên tố -> phân tán tốt)
    std::size_t bam(const std::string& khoa) const {
        unsigned long h = 0;
        for (std::size_t i = 0; i < khoa.size(); ++i)
            h = h * 31u + (unsigned char)khoa[i];
        return (std::size_t)(h % soBucket);          // soBucket = 211 (số nguyên tố)
    }

public:
    void dat(const std::string& khoa, const V& gt) {
        std::size_t i = bam(khoa);
        for (Nut* p = bang[i]; p != 0; p = p->tiep)
            if (p->khoa == khoa) { p->giaTri = gt; return; }   // đã có -> cập nhật
        Nut* moi = new Nut(khoa, gt);
        moi->tiep = bang[i];  bang[i] = moi;                   // chèn đầu chuỗi: O(1)
        ++demSo;
    }
    bool lay(const std::string& khoa, V& ketQua) const {
        for (Nut* p = bang[bam(khoa)]; p != 0; p = p->tiep)
            if (p->khoa == khoa) { ketQua = p->giaTri; return true; }
        return false;
    }
    std::size_t chuoiDaiNhat() const;    // để ĐÁNH GIÁ chất lượng hàm băm
};

Độ phức tạp: O(1) trung bình; xấu nhất O(n) nếu mọi khoá dồn vào một ô. Hàm chuoiDaiNhat() cho biết chuỗi dài nhất — số càng nhỏ, hàm băm càng tốt. Menu Tìm kiếm → 1 của chương trình in ra chỉ số này.

Lý thuyết cốt lõi

1. Tìm tuyến tính — O(n), luôn dùng được

template <class T, class DieuKien>
long timTuyenTinh(const Vector<T>& a, DieuKien dk) {
    for (std::size_t i = 0; i < a.kichThuoc(); ++i)
        if (dk(a[i])) return (long)i;
    return -1;
}

Ưu điểm: không cần dữ liệu sắp xếp, tìm được theo bất kỳ điều kiện. PBL2 dùng nó cho tìm gần đúng theo tên sách (chuỗi con).

2. Tìm nhị phân — O(log n), cần đã sắp xếp

template <class T, class K, class LayKhoa>
long timNhiPhan(const Vector<T>& a, const K& khoa, LayKhoa layKhoa) {
    long tra = 0, phai = (long)a.kichThuoc() - 1;
    while (tra <= phai) {
        long giua = tra + (phai - tra) / 2;      // viết vậy để không tràn số
        K    kg   = layKhoa(a[(std::size_t)giua]);
        if      (kg == khoa) return giua;
        else if (kg <  khoa) tra  = giua + 1;    // bỏ nửa trái
        else                 phai = giua - 1;    // bỏ nửa phải
    }
    return -1;
}

Mỗi lần lặp loại bỏ một nửa dữ liệu. Với 1.000.000 phần tử chỉ cần ≈ 20 phép so sánh (vì 2²⁰ ≈ 10⁶) trong khi tuyến tính cần tới 1.000.000.

3. Quick Sort — O(n log n) trung bình

template <class T, class SoSanh>
void quickSortDeQuy(Vector<T>& a, long tra, long phai, SoSanh cmp) {
    if (tra >= phai) return;
    T    moc = a[(std::size_t)(tra + (phai - tra) / 2)];   // chọn mốc ở GIỮA
    long i = tra, j = phai;
    while (i <= j) {
        while (cmp(a[(std::size_t)i], moc)) ++i;   // từ trái, tìm phần tử >= mốc
        while (cmp(moc, a[(std::size_t)j])) --j;   // từ phải, tìm phần tử <= mốc
        if (i <= j) { a.doCho((std::size_t)i, (std::size_t)j); ++i; --j; }
    }
    quickSortDeQuy(a, tra, j, cmp);       // đệ quy nửa trái
    quickSortDeQuy(a, i, phai, cmp);      // đệ quy nửa phải
}

Rất nhanh trong thực tế, sắp xếp tại chỗ (không cần bộ nhớ phụ). Nhược điểm: không ổn định (hai phần tử bằng nhau có thể đổi thứ tự) và xấu nhất O(n²).

4. Merge Sort — O(n log n) mọi trường hợp, ổn định

template <class T, class SoSanh>
void tron(Vector<T>& a, std::size_t tra, std::size_t giua, std::size_t phai,
          Vector<T>& tam, SoSanh cmp) {
    std::size_t i = tra, j = giua + 1, k = tra;
    while (i <= giua && j <= phai) {
        if (cmp(a[j], a[i])) tam.datLai(k++, a[j++]);
        else                 tam.datLai(k++, a[i++]);   // bằng nhau -> ưu tiên bên TRÁI
    }                                                    // -> đó là tính ỔN ĐỊNH
    while (i <= giua) tam.datLai(k++, a[i++]);
    while (j <= phai) tam.datLai(k++, a[j++]);
    for (std::size_t t = tra; t <= phai; ++t) a.datLai(t, tam[t]);
}

3. Sinh mã tự động

Yêu cầu: “Mã sách, mã khách hàng, mã hoá đơn là duy nhất và được chương trình sinh tự động”. Cách làm: tìm số lớn nhất đang có sau tiền tố, rồi cộng 1.

template <class T>
std::string KhoDuLieu<T>::sinhMa(const std::string& tienTo, int soChuSo) const {
    long lonNhat = 0;
    for (std::size_t i = 0; i < ds.kichThuoc(); ++i) {
        std::string m = ds[i].getMa();
        if (m.size() > tienTo.size()
            && veThuong(m.substr(0, tienTo.size())) == veThuong(tienTo)) {
            long v = atol(m.substr(tienTo.size()).c_str());
            if (v > lonNhat) lonNhat = v;
        }
    }
    std::ostringstream os;
    os << tienTo << std::setw(soChuSo) << std::setfill('0') << (lonNhat + 1);
    return os.str();                // "KH001", "HD00007", ...
}

Vector<MucBanChay> CuaHang::bangSachBanChay() const {
    Vector<MucBanChay> kq;
    BangBam<int>       viTri;                // mã sách -> chỉ số trong kq

    const Vector<HoaDon>& ds = khoHoaDon.duLieu();
    for (size_t i = 0; i < ds.kichThuoc(); ++i) {
        const Vector<DongChiTiet>& dong = ds[i].cacDong();
        for (size_t j = 0; j < dong.kichThuoc(); ++j) {
            std::string ma = dong[j].getMaSach();
            int vt;
            if (!viTri.lay(ma, vt)) {                    // gặp lần đầu -> tạo mục mới
                kq.them(MucBanChay(ma, dong[j].getTenSach()));
                vt = (int)kq.kichThuoc() - 1;
                viTri.dat(ma, vt);
            }
            kq[(size_t)vt].soLuongBan += dong[j].getSoLuong();
            kq[(size_t)vt].doanhThu   += dong[j].thanhTien();
        }
    }
    quickSort(kq, bcTheoSoLuongGiam);        // sắp giảm dần -> top bán chạy
    return kq;
}

std::string bamMatKhau(const std::string& mk) {
    unsigned long h = 5381;                          // hàm băm djb2
    for (size_t i = 0; i < mk.size(); ++i)
        h = ((h << 5) + h) + (unsigned char)mk[i];   // h*33 + ký tự
    std::ostringstream os;  os << std::hex << h;
    return os.str();
}

4. Chuẩn hoá mã nguồn

  • Đặt tên nhất quán: lớp PascalCase, hàm và biến camelCase, hằng VIET_HOA. Toàn dự án dùng tiếng Việt không dấu, đọc là hiểu: ghiNhanHoaDon, tiLeGiamThanhVien.
  • Chú thích cái “vì sao”, không chú thích cái “làm gì”. Dòng i++; // tăng i là vô ích. Dòng // làm việc trên BẢN SAO để không phá thứ tự theo mã mới có giá trị.
  • Mỗi hàm một việc. Hàm dài hơn 50 dòng thường là dấu hiệu nên tách.
  • Không lặp code. Thấy chép 3 lần → nghĩ tới template hoặc hàm chung.

Nếu bạn bị chậm tiến độ

Thứ tự ưu tiên cắt giảm (cắt từ dưới lên): ① biểu đồ cột → ② thống kê theo khoảng thời gian → ③ danh sách liên kết (dùng Vector thay) → ④ Merge Sort (chỉ giữ Quick Sort) → ⑤ sao lưu. Tuyệt đối không cắt: 4 cây kế thừa, đa hình, template, ngoại lệ, đọc/ghi tệp, nghiệp vụ nhập – bán. Đó là phần thể hiện bạn hiểu OOP và là phần chấm điểm chính.

Lời cuối

Sáu nghìn dòng code không đáng sợ nếu bạn viết nó thành mười bốn lần, mỗi lần vài trăm dòng, và mỗi lần đều chạy được trước khi đi tiếp. Đó là toàn bộ ý tưởng của tài liệu này.

Điều thầy cô đánh giá không phải là chương trình dài bao nhiêu, mà là bạn có giải thích được vì sao mình thiết kế như vậy hay không: vì sao Sach phải trừu tượng, vì sao hàm hủy phải ảo, vì sao sắp xếp trên bản sao, vì sao kiểm tra hết rồi mới trừ kho. Mỗi câu “vì sao” đó đều đã được trả lời ở một chặng trong tài liệu này. Hãy học để trả lời được, đừng học để nhớ cú pháp.
